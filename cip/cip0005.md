# CIP-0005: Move W&CP volume supplemental files onto per-paper -supp extras

> **Note**: CIPs describe HOW to achieve requirements (WHAT).
> This CIP implements [REQ-0004](../requirements/req0004_volume-level-supplemental.md).

## Summary

A few JMLR W&CP challenge volumes still keep appendices in `gh-pages/supplemental/` and (sometimes) point at them with `supplementalurl`. The current theme never renders that field. The modern path is per-paper `{id}-supp.*`, stored beside the paper and listed in `post.extras`.

This CIP migrates those leftovers onto the papers that cite them, using the same `-supp` naming and extras YAML as new volumes. It does **not** add a `volume_extras` theme feature.

Open issues [v16#1](https://github.com/mlresearch/v16/issues/1) and [v27#2](https://github.com/mlresearch/v27/issues/2) close once their PDFs are linked from `guyon11a` and `silver12a`. The same treatment applies to v3 and v6, which have the same unlinked `supplemental/` tree but no GitHub issues.

**Which requirements does this CIP address?** REQ-0004.

## Motivation

Readers looking for challenge dataset reports currently have to find GitHub trees. The files are already published (for example `/v16/supplemental/Datasets_AL_challenge.pdf`) but the volume index does not link them.

The pipeline already knows how to attach extras: `create_volume.rb` moves `{id}-supp.*` next to the paper and writes `extras`. These historical volumes were generated before that convention. The smallest consistent fix is to put the files on that path by hand, not to invent a second extras mechanism for five old volumes.

## Detailed Description

### How widespread is this?

Probed `gh-pages/supplemental/` on v1–v60 (plus the known Guyon challenge volumes). Five volumes have the directory. None of v29–v60 do. This is a closed historical set, not an ongoing editor practice.

| Volume | Event | Durable files in `supplemental/` | Attach to | Notes |
| --- | --- | --- | --- | --- |
| v3 | Causation and Prediction Challenge (WCCI 2008) | `Datasets_WCCI08_challenge.pdf`, `FactSheets_WCCI08_challenge.pdf`, `Software_WCCI08_challenge.pdf` | `guyon08a` | No `supplementalurl`. Three PDFs, no HTML index. |
| v6 | Causality: Objectives and Assessment (NIPS 2008) | Nine team fact-sheet PDFs + `JMLRWCP_V6_supplemental.html` | `guyon10a` | Fact sheets do **not** match v6 paper ids (Ping He, Jin Tian, Pellet, …). They stay on the overview paper. |
| v7 | KDD-Cup 2009 | HTML only (`JMLRWCP_V7_supplemental.html`) | — | `supplementalurl` set; HTML points at kddcup-orange.com. Nothing to rename to `-supp`. |
| v16 | Active Learning Challenge (AISTATS 2010) | Dataset + software PDFs + two HTML indexes | `guyon11a` | [v16#1](https://github.com/mlresearch/v16/issues/1). Leftover `JMLRWCP_V15_supplemental.html` is the wrong volume; do not link it. |
| v27 | Unsupervised and Transfer Learning (ICML 2011) | `datasetsutl12a.pdf` + HTML index | `silver12a` | [v27#2](https://github.com/mlresearch/v27/issues/2). Filename looks like a paper stub; there is no `datasetsutl12a` post. |

So it is not “a couple of random papers across the archive.” It is **four challenge-overview papers** (`guyon08a`, `guyon10a`, `guyon11a`, `silver12a`) plus v7 HTML that we can ignore or clean as dead config.

v46 has a BibTeX `note` pointing at an *external* causality.inf.ethz.ch copy of the UTL HTML. That is unrelated; leave it.

Do not wait on Isabelle Guyon. Linking files already in the repo restores access.

### Why not `volume_extras`?

These appendices are cited from a single overview / challenge-report paper. The theme already loops `post.extras` on the volume index next to that paper. Putting the files on `{id}-supp.*` reuses that path.

`create_volume.rb` globs `{id}-supp.*` (one file per extension, typically `{id}-supp.pdf`). `check_volume.rb` uses `/-supp\.(pdf|zip|tar\.gz)$/`. Several of these papers have **more than one PDF**. Do not zip them into one `-supp.zip` (worse for readers). Do not add a theme `volume_extras` list.

Convention for these volumes:

1. **Primary dataset / design report** → `{id}-supp.pdf` (matches the modern glob).
2. **Software report** → `{id}-software.pdf` and the existing paper `software:` field (the theme already renders a Software link).
3. **Any further PDFs** (v3 fact-sheets bundle; v6’s nine team sheets) → `{id}-supp-{slug}.pdf` listed as extra `extras:` entries with human labels. Hand-written YAML; we are not re-running `create_volume.rb` on these volumes.

HTML indexes stay unlinked (SSI includes, copy-paste titles, `file:///` leftovers). After the PDFs move, delete or leave the HTML in `supplemental/` as archaeology; do not serve them as the public extra.

### Frontmatter contract (theme + `_posts`)

The jekyll-theme does not glob files. `layout: inproceedings` includes `paper_abstract.html`; the volume index includes `listpaper.html`. Both read the same post keys via `extractinfo_publication.html`:

| YAML key | Shape | Visible label |
| --- | --- | --- |
| `pdf` | URL string | Download PDF |
| `software` | URL string | Software |
| `supplementary` | URL string | Supplementary Material (legacy `inc_layout` path; do not use) |
| `extras` | list of `{label, link}` | `label` as written |

That is the same schema `lib/mlresearch.rb` `extractpapers` writes. A current post looks like `pdf: …` plus `extras: []` or a filled extras list; `software:` is a URL when present (for example a GitHub repo). Old v16/v27 posts already use `layout: inproceedings` and `pdf: http://proceedings.mlr.press/v16/guyon11a/guyon11a.pdf`. They simply omit `extras` / `software`. Adding those keys is the format, not a theme change.

Example for `guyon11a` (URLs match the existing `pdf:` host/path, not `raw.githubusercontent.com`, because this volume still publishes from `gh-pages`):

```yaml
software: http://proceedings.mlr.press/v16/guyon11a/guyon11a-software.pdf
extras:
- label: Supplementary PDF
  link: http://proceedings.mlr.press/v16/guyon11a/guyon11a-supp.pdf
```

`label: Supplementary PDF` is what `extractpapers` uses for `{id}-supp.pdf`. Dropping the file next to `guyon11a.pdf` is not enough on its own; the extras list has to be in the post.

`software:` always renders as “Software”. That matches the template. These files are software *reports* (PDFs), not code repos. If that wording is too terse, put the software PDF in `extras` with label `Software report` instead — still the extras schema, no theme change. Either choice is valid YAML for the current templates.

### Where the files live (old vs new tree)

These volumes still publish from `gh-pages` with paper PDFs at `{id}/{id}.pdf` (for example `https://proceedings.mlr.press/v16/guyon11a/guyon11a.pdf`). A full split onto `main/assets/` for v3/v6/v16/v27 is a separate migration and is **out of scope**.

Consistency here means **the same names and extras YAML**, in the tree these volumes already use:

```
gh-pages/guyon11a/guyon11a.pdf
gh-pages/guyon11a/guyon11a-supp.pdf
gh-pages/guyon11a/guyon11a-software.pdf
```

Use `git mv` from `supplemental/` into `{id}/`. Then set `extras` / `software` on the post. After Pages rebuild, links are `/v16/guyon11a/guyon11a-supp.pdf` (same pattern as the paper PDF). Old `/vN/supplemental/*.pdf` URLs will 404; mention the new URLs when closing the GitHub issues.

### File mapping

**v3 `guyon08a`**

| Current | New |

| `FactSheets_WCCI08_challenge.pdf` | `guyon08a/guyon08a-supp-factsheets.pdf` + extras label |

**v6 `guyon10a`**

Nine fact sheets → `guyon10a/guyon10a-supp-fs1.pdf` … `fs9.pdf` (keep the original team name in the extras label). No single “dataset report” PDF in this folder; there is no `{id}-supp.pdf` unless we pick FS1 as primary. Prefer sequential `-supp-fsN` names and extras only, rather than arbitrarily promoting one sheet.

| Current | New |

No PDFs. Remove unused `supplementalurl` (and the empty Supplemental `sections` entry if it renders a blank heading). Leave the HTML in git or delete in the same cleanup; do not link it.

## Implementation Plan

1. **v16 and v27 first** (closes the open issues)
   - `git mv` PDFs into the paper directories with the names above.
   - Add `extras` / `software` to the two posts.
   - After Pages rebuild, confirm links on the volume indexes.
   - Close [v16#1](https://github.com/mlresearch/v16/issues/1) and [v27#2](https://github.com/mlresearch/v27/issues/2) with the new URLs.

2. **v3 and v6**
   - Same move + YAML pattern for `guyon08a` and `guyon10a`.
   - v6 extras labels taken from the HTML fact-sheet titles.

3. **v7 cleanup**
   - Drop dead `supplementalurl` / empty Supplemental section.

4. **Do not**
   - Add `volume_extras` to jekyll-theme.
   - Teach `create_volume.rb` to glob `supplemental/`.
   - Re-host or rewrite the W&CP HTML indexes.
   - Migrate these volumes from `gh-pages/{id}/` to `main/assets/`.
   - Wait for editor sign-off.

## Backward Compatibility

- Other papers and volumes are untouched.
- `{id}-supp.*` behaviour for new volumes is unchanged.
- Old `/vN/supplemental/*.pdf` URLs break after `git mv`. That is acceptable: they were unlinked from the proceedings page. GitHub issue comments should give the new URLs.
- Paper PDFs and citekeys are untouched.

## Testing Strategy

- After each volume’s Pages rebuild, open the volume index and the overview paper: extras/software labels present, URLs return PDFs.
- Confirm `/vN/supplemental/` no longer lists the moved PDFs (or 404s).
- No `create_volume.rb` test: these volumes are not regenerated.
