## Summary

Add a unified **`pmlint`** CLI that volume editors and CI can run against a volume tree. Like other linters, it supports:

- **`--check`** (default): non-mutating report; exit `1` on failure — what pull-request CI runs
- **`--fix`**: apply safe, non-interactive repairs from existing tidy tools, then re-check

Before running checks, the tool **always updates itself from the papersite
source repository** (fetch; fast-forward when behind) so volume repos lint
against current rules. A one-shot **install** places `pmlint` on `PATH` and
ensures a cache clone exists; after that, every run self-updates.

This CIP does **not** invent new validators. It composes what already exists (`check_volume`, `tidy_bibtex`, optionally `tidy_bib_unicode --strict`) and is the concrete **Phase 1** of [CIP-0004](cip0004.md) (PR validation), without taking on auto-create or deploy.

**Requirements addressed:** [REQ-0003](../requirements/req0003_bibtex-validation-prevents-pipeline-failures.md) (BibTeX validation prevents pipeline failures). A dedicated “PR lint gate” requirement may be added later if needed.

## Motivation

Proceedings editors submit volume repositories with BibTeX and PDFs that must meet papersite conventions before `create_volume` / deploy. Today that gate is manual:

```bash
../papersite/bin/check_volume.sh 304
ruby ../papersite/lib/tidy_bibtex.rb --strict --check-author-commas proceedings.bib
```

Problems:

1. **No single entrypoint** — editors must know which scripts to run and in what order
2. **Stale tooling** — a sibling `papersite` clone can drift behind `main`, so local checks disagree with current policy
3. **PR CI does not run volume checks** — only `.github/workflows/test-bibtex-cleaner.yml` exists, and it tests the cleaner in papersite, not submitted volumes
4. **`--fix` is incomplete** — `check_volume.rb` documents `--fix` but does not implement it; tidy tools have fix flags that are not wired into one flow

[CIP-0004](cip0004.md) already proposes full CI/CD. That scope is large (compile, deploy, PR comments). This CIP narrows Phase 1 to `pmlint` with check/fix modes and a PR gate that calls `--check`.

Aligns with project tenets:

- **Automation with guardrails** — automate the boring check; mutate only behind explicit `--fix`
- **Data integrity over convenience** — fail hard on invalid BibTeX / misplaced PDFs rather than “mostly works”
- **Reproducible, auditable pipeline** — one command, same rules locally and in CI, always from current papersite source

## Detailed Description

### Architecture

```
pmlint [--check|--fix] [VOLUME] [BIBFILE]
        │
        ├─ 1. Resolve PAPERSITE_ROOT (env, sibling ../papersite, or clone)
        ├─ 2. Self-update: git fetch + fast-forward (or shallow checkout in CI)
        ├─ 3. If --fix: tidy_bibtex --fix-percent (non-interactive only)
        ├─ 4. tidy_bibtex --strict --check-author-commas
        ├─ 5. bin/check_volume.sh (PDF/supp placement, keys, proceedings fields, …)
        ├─ 6. Optional: tidy_bib_unicode --strict (report only in v1)
        └─ 7. Summary + exit 0/1
```

### Self-update contract

**Every `pmlint` invocation updates automatically before checks** (unless
`PMLINT_SKIP_UPDATE=1`). There is no separate “update” command editors must
remember.

1. Resolve papersite root in order:
   - `PAPERSITE_ROOT` if set
   - Sibling directory `../papersite` relative to the volume cwd
   - Install/cache clone (see Install below), e.g. `~/.cache/papersite` or
     `~/.local/share/papersite`
2. In that tree:
   - `git fetch origin` on the default branch (typically `main`)
   - If local HEAD is behind `origin/main`, fast-forward update
   - If already up to date, continue (no-op update)
   - If the working tree is dirty and cannot fast-forward, **fail clearly**
     (do not silently use stale or mixed state), unless skip-update is set
3. Invoke all Ruby/shell tools **from that refreshed tree**, never from a
   vendored copy inside the volume repo.

In GitHub Actions, “self-update” is satisfied by checking out
`mlresearch/papersite@main` (or a pinned SHA for reproducibility
experiments) into the job workspace and setting `PAPERSITE_ROOT` (and
typically `PMLINT_SKIP_UPDATE=1` so the job does not re-fetch).

### Install

Editors should be able to install `pmlint` once and then run it from any
volume directory without manually managing a papersite checkout.

v1 install contract:

1. **One-shot installer** (script in papersite, e.g. `bin/install-pmlint` or
   documented `curl`/`bash` from the repo) that:
   - Clones `mlresearch/papersite` into the cache path if missing
   - Places a `pmlint` shim on `PATH` (e.g. `~/.local/bin/pmlint`) that
     delegates to `$PAPERSITE_ROOT/bin/pmlint` after the self-update step
   - Prints how to verify (`pmlint --help` / `pmlint --check …`)
2. **Idempotent**: re-running install refreshes the shim and ensures the
   cache clone exists; it does not require uninstall first
3. **Document** in root `README.md`: install → `cd vNNN` → `pmlint --check NNN`

Developers who already keep a sibling `~/mlresearch/papersite` can skip
install and call `../papersite/bin/pmlint` directly; that path still
self-updates on each run.

### Modes

| Mode | Behaviour | Exit |
|------|-----------|------|
| `--check` (default) | **Read-only.** Must not create, modify, or delete any file under the volume tree (and should not leave temp artifacts there). Run tidy strict checks + `check_volume`. Unicode map gaps are check failures, not auto-fixed. | `0` all pass; `1` any failure |
| `--fix` | Mutating. Run `tidy_bibtex --fix-percent` (and only other **documented non-interactive** safe repairs), then run the same checks as `--check`. | Same |

**`--check` invariant:** composition must not rely on tools that write the BibTeX (or anything else) as a side effect. Today `tidy_bibtex.rb` always writes an output file; v1 must add a `--dry-run` (or equivalent) path so strict/author-comma checks report without writing. Writing under `/tmp` and deleting is a last resort, not the preferred design.

**Out of scope for v1 `--fix`:**

- Interactive Unicode replacement / editing `unicode_replacements.yml`
- Moving stranded PDFs or supplementary files into the volume root (`check_volume --fix`) — document as a follow-on task
- Running `create_volume` or `deploy_volume`

### Composition (reuse existing tools)

| Concern | Tool |
|---------|------|
| PDF/supp at volume root; key↔PDF; orphans; proceedings fields; author format; non-ASCII keys; non-printables | `bin/check_volume.sh` → `lib/check_volume.rb` |
| `%` escaping; author-comma reporting | `lib/tidy_bibtex.rb` |
| Unicode → LaTeX coverage (check only in v1) | `lib/tidy_bib_unicode.rb --strict` |

Do not duplicate these validators in the `pmlint` wrapper.

### CLI UX (sketch)

```bash
# From volume directory v304/
../papersite/bin/pmlint --check 304
../papersite/bin/pmlint --fix 304 proceedings.bib

# Explicit papersite root
PAPERSITE_ROOT=~/mlresearch/papersite \
  $PAPERSITE_ROOT/bin/pmlint --check 304
```

Entrypoint: `bin/pmlint` (thin shell wrapper; optional `lib/pmlint.rb` orchestrator if sequencing needs more than shell). Prefer the smallest wrapper that sequences existing CLIs with clear section headers and a final summary.

### PR / CI wiring

Add a reusable workflow (or documented workflow snippet) that volume repositories can enable:

1. Checkout the volume PR
2. Checkout `mlresearch/papersite` (latest `main`, or pinned)
3. Install Ruby deps if required by tidy/check scripts
4. Run `pmlint --check <volume>`
5. Fail the job on exit `1` (optional later: PR comment with the summary — nice-to-have, not required for v1)

This implements CIP-0004 Phase 1’s validation intent without auto-compile or deploy.

## Implementation Plan

1. **Entrypoint, install, and self-update**
   - Add `bin/pmlint` (and thin orchestrator if needed)
   - Resolve `PAPERSITE_ROOT`; **always** fetch and fast-forward when behind
     (`PMLINT_SKIP_UPDATE=1` escape hatch only)
   - Add install script / PATH shim (idempotent first-time setup + cache clone)
   - Document install + usage in root `README.md`

2. **Compose check path**
   - Add `tidy_bibtex --dry-run` (or equivalent) so strict/author-comma checks do not write
   - Sequence: tidy dry-run strict + author commas → `check_volume` → optional unicode `--strict` (read-only / no write)
   - Unified exit code and readable failure summary
   - Verify `--check` leaves the volume tree bit-identical

3. **Compose fix path**
   - `--fix` runs `tidy_bibtex --fix-percent`, then the check path
   - Document explicitly what is and is not auto-fixed

4. **CI / PR gate**
   - Add workflow under papersite (reusable or example) that runs `--check`
   - Document how a volume repo enables it
   - Cross-link from CIP-0004 Phase 1

5. **Tests**
   - Smoke tests for the wrapper (check fails on known-bad fixture; passes on known-good)
   - Assert `--check` does not modify any file under the fixture volume
   - Reuse fixtures from `tests/test_check_volume.sh` where possible

6. **Follow-on (post-v1, may be separate backlog tasks after Accept)**
   - Implement real `check_volume --fix` (e.g. move stranded PDFs to root)
   - PR comment bot with validation report
   - Optional auto unicode tidy when map already covers all characters

## Backward Compatibility

- Existing `bin/check_volume.sh` and tidy CLIs remain unchanged and callable directly
- Volume repos that already invoke `check_volume` keep working
- New entrypoint is additive
- CI for volumes is opt-in via workflow until volume templates ship with it by default

## Testing Strategy

- Unit/smoke: wrapper argument parsing; skip-update path; failure aggregation
- Integration: run `--check` against existing `tests/` fixtures for `check_volume`
- Manual: run `--check` / `--fix` on a recent real volume directory with a sibling papersite clone
- CI: papersite workflow that exercises the lint wrapper against a small fixture volume (does not require every volume repo to exist)
